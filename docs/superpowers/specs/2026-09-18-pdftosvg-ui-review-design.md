# PdfToSvg 画面の見直し 設計仕様

- 日付: 2026-09-18
- 対象: `pdf-to-svg/`（Web UI・`state` RPC・テスト・原稿 4 冊・画面写真）
- 状態: 利用者承認済みのモックアップに基づく設計。実装計画はこの仕様の承認後に別途作成する。
- モックアップ: スマホ版 <https://claude.ai/artifact/M6zfosyxbWAN8JcPC3jP5A> ・ キャンバス版 <https://claude.ai/artifact/XJGyWNJ2LSdsh99p3gNyEM>

## 1. 決定事項（利用者の判断）

1. 手順 2・3 の**ページごとの確認（要確認 / 確認済み / スキップ）を無くす**。黄色い確認バー、まとめてスキップ、範囲指定、書き出しの「スキップを除く」も撤去する。除外したいページは「ページを指定」で行う。
2. 手順 2・3 の画面下に**指定のページへ移動する部品**（ファイル選択 + ページ番号 + 前後）を置く。
3. 手順 1 のスキャン画像の案内を、モーダルとトーストから**常設バナー + ファイルカードのバッジ**へ移す。「必ず読ませる」ためのチェック（B 案）は付けない。
4. 手順 1 の「図だけをグレースケールで書き出す」チェックボックスを**「書き出し方」の 2 択カード**にする。
5. 手順 2 の右パネルは一致箇所ごとの「置換 / 戻す」に絞り、件数カードは 0 件でも緑にしない。
6. 手順 3 のレールは「編集したページ」を件数と内容で示し、右パネルは「このページの編集」の一覧と使い方に絞る。
7. 手順 4 のまとめを表にし、説明だけの緑カードを 1 行の注記にする。
8. Undo / Redo に文字ラベルを付ける。

## 2. 変えないこと

- サーバ側の編集モデル（コマンドと Undo）、辞書、書き出し（`exportSvg` / zip）、グレーモードの図の選択画面（手順 4）。
- 不可視 OCR 文字層・要素数超過・背景色の採色失敗のトースト（スキャン画像のトーストだけを廃止する）。
- 手順 2 で純スキャンページを対象外にする判定（`Page.is_scanned` → `state` の `scanned[]`）。全ページ対象外なら手順 2 を省略する遷移も維持する。ただし判定の置き場所を `status2` の `"na"` から `S.scanned` へ移す（4.1 節）。
- E2E 用サーバ、セキュリティ関連（`origin_guard` など）。

## 3. 画面仕様

### 3.1 共通

- トップバーの Undo / Redo は、アイコンの右に「元に戻す」「やり直し」の文字を出す（`title` は残す）。
- 黄色い確認バー（`#guard`）、右パネル下部の「確認しました / スキップ」（`#pageact-2` / `#pageact-3`）、状態の凡例（`#sum-2` / `#sum-3`）は DOM ごと撤去する。
- 「次へ」は手順 2 → 3、手順 3 → 4 のいずれも無条件に進む。
- **説明文の書き方**: 画面に出す説明文は 1 文ごとに改行する（句点で改行。1 段落に複数の文を続けない）。手順を含む「使い方」は 1 文 1 項目の箇条書きにする。対象は手順 1 のバナー、手順 2 の件数カード、手順 3 のパネル説明と「使い方」、手順 4 の説明文と注記。
- 手順 3 の「使い方」は表示中のページで文言を切り替える。通常のページは「要素をクリックして「削除」」「「範囲削除」でドラッグした範囲をまとめて削除」「「枠線」「上書き」はドラッグで置きます」「置いた後も動かせます」。スキャン画像のページは「文字は画像なので、辞書では置き換えられません」「「上書き」を選び、置き換えたい所をドラッグします」「上のボックスに語を入れると、画像の上に矩形と語が乗ります」「置いた上書きは後から動かせます」。

### 3.2 手順 1「PDF を選ぶ」

- **書き出し方**（`.modebox` を置き換える）: ラジオ 2 択のカード。
  - 「ページを SVG にする」（既定）: 説明「用語を置き換え、いらない部分を消してから書き出します。」流れ「1 PDF › 2 用語 › 3 削除・枠線 › 4 SVG」。
  - 「図だけをグレースケールで書き出す」: 説明「『当社のスチュワードシップ活動』の図を自動で見つけて候補にします。」流れ「1 PDF › 4 図を選ぶ・SVG」。
  - 入力は `input[type=radio][name=mode]`（`#mode-normal` / `#mode-gray`）。`S.gray` の意味は変えない（`#mode-gray` が ON のとき true）。ステップバーの表示切り替え（手順 2・3 を隠す、`#step4-label`）は現行のまま。
- **スキャン画像のバナー**（`#scan-banner`）: ファイル一覧の見出しとカードの間に置く。スキャン画像のページが 1 ページ以上あるときだけ表示する。
  - 全ページがスキャン画像: 「スキャン画像のページが N ページあります。文字を持たないため、用語の置換はできません。手順 2「用語を置換」は省略します。文字を置き換えたいときは、手順 3 の「上書き」で矩形と語を置きます。」
  - 混在: 「スキャン画像のページが N ページあります。文字を持たないため、用語の置換はできません（手順 2 の一覧には出ません）。文字を置き換えたいときは、手順 3 の「上書き」で矩形と語を置きます。」
  - グレーモードのときは表示しない（手順 2 を通らないため）。
- **ファイルカードのバッジ**: スキャン画像のページを 1 ページ以上持つファイルのカードに「スキャン画像 n / m ページ」（n = そのファイルのスキャンページ数、m = ページ数）を出す。
- 撤去: `#skip2-dialog`、読み込み直後の「N ページはスキャン画像のため…」トースト。ステップバーの `#scan-skipnote`（「手順 2 は省略されます（スキャン画像のみのため）」）は残す。
- フッターの案内: 通常「「次へ」で用語の置換に進みます」。スキャンページがあるときは「（スキャン画像の N ページは対象外）」を添える。全ページがスキャン画像のときは現行どおり「「次へ」で削除・枠線の編集に進みます（スキャン画像のみのため用語の置換は省略）」。

### 3.3 手順 2「用語を置換」

- **レール**（`#pagenav`）
  - 見出し: 「全 N ページ　辞書に一致 n ページ　対象外 k」（k はスキャンページ数。0 なら省略）。
  - 絞り込み `select.pl-filter`: 「辞書に一致したページだけ」（既定）/「すべてのページ」。どちらでもスキャンページは出さない。
  - 行 `.pg-row2`: 丸数字（ファイル内ページ番号）+「n ページ」+ 右端タグ。タグは「置換 a ・ 未置換 b」（0 の側は省略。両方 0 なら無し）。表示中のページは `current`。行クリックでそのページへ移動（現行どおり）。
  - ファイル行 `.pl-file` は名前・行数・折りたたみだけ。チェックボックスは無し。
  - 撤去: 「表示中をすべて選択」、「未確認をまとめてスキップ」、範囲指定（`.pl-range`）、選択バー（`.pl-selbar`）、行のチェックボックス。
- **右パネル「確認」タブ**
  - 件数カード（中立の `--sunk` 背景）: 大きく「置き換えた語の数」、見出し「このページで置き換えた語」、説明「辞書に一致した M か所のうち b か所は「未置換」です。「置換」で当てられます。」（b = 0 なら「辞書に一致した M か所をすべて置き換えました。」、M = 0 なら「このページに辞書と一致する語はありません。」）。緑の完了表示はしない。
  - 一致箇所の一覧: 現行の `.change-row`（番号マーカー・元の語 → 置換後・未置換バッジ・「置換」「戻す」）を維持。
  - スキャンページを表示しているとき: 「このページはスキャン画像のため、用語の置換の対象外です」（現行の文言）。
  - パネル下部（`.panel-foot`）: 「前のページ」「次の一致ページ」の 2 ボタン。「次の一致ページ」は表示中より後ろで一致（置換 + 未置換 > 0）のあるページへ。無ければ先頭から探し、それも無ければ無効。
- **画面下のページ移動**（3.5 節の共通部品）。
- フッターの案内: 「用語の置換 — 辞書に一致 n ページ ・ 置換 a か所 / 未置換 b か所」。
- 手順 2 に入ったときの表示ページ（`landOnPhase2`）: 一致のあるページがあればその最初、無ければスキャン以外の最初のページ。

### 3.4 手順 3「削除・枠線の編集」

- **レール**（`#pagenav-3`）
  - 見出し: 「全 N ページ　編集したページ n」。
  - 絞り込み: 「すべてのページ」（既定）/「編集したページだけ」。スキャンページも出す（上書きの対象になるため）。
  - 行のタグ: 「削除 a ・ 枠線 b ・ 上書き c」（0 の項目は省略。すべて 0 なら無し）。
- **右パネル**
  - 見出し「削除・枠線の編集」、説明「編集は自動で保存されます。編集しないページはそのまま書き出されます。」
  - 「このページの編集」の一覧: 削除した要素（現行の `removedList` の行。「戻す」）、枠線（色・太さ。「削除」）、上書き（置換語。「削除」）。いずれも無ければ「このページに編集はありません」。
  - パネル下部に固定の「使い方」（3 行の短い説明）と、「前のページ」「次のページ」の 2 ボタン。
- 撤去: レールのチェックボックス・一括操作・範囲指定・状態の凡例・「確認しました / スキップ」。
- フッターの案内: 「削除・枠線の編集 — 編集したページ n / N」。

### 3.5 ページへ移動（手順 2・3 の共通部品）

- 場所: キャンバス下の `.page-nav`（現行は「ファイル名 ・ n ページ」の文字だけ）を置き換える。
- 構成: `‹`（前のページ）／ ファイル選択 `select`（`S.FILES` の名前）／ ページ番号入力 `input[type=number]`（1〜そのファイルのページ数）／「/ m ページ」／「移動」ボタン／ `›`（次のページ）。
- 動き: 「移動」または番号入力での Enter で `S.page` をその通しページに変える。前後ボタンは通し番号で ±1（ファイルをまたぐ。端では無効）。ページが変わったら入力値と選択を追従させる。
- レールの絞り込みに出ていないページへも移動できる。手順 2 でスキャンページへ移動した場合は 3.3 節の対象外表示を出す。
- 実装は `page-jump.js` の 1 部品に閉じ、手順 2・3 で同じ関数から 2 つ生成する（`rect-overlay.js` と同じ「1 本を共有」の流儀）。

### 3.6 手順 4「SVG に書き出す」

- 説明文: 「内容を確かめて、右下の「SVG に書き出す」を押します。ファイルはダウンロードフォルダーに保存されます。」
- まとめ（`#export-summary`）を表にする（左に大きく「N 個の SVG」）:
  - PDF: 「F ファイル・全 N ページ」
  - 用語の置換: 「置換 a か所（p ページ）・ 未置換 b か所 ・ 対象外（スキャン画像） k ページ」（0 の項目は省略）
  - 削除・枠線: 「編集したページ n（削除 x ・ 枠線 y ・ 上書き z）」（n = 0 なら「編集したページはありません」）
- 書き出す範囲: 「表示中のページのみ / 全ページ / ページを指定」の 3 択。「スキップを除く」（`#exp-noskip`、`noskip`）を撤去する。範囲の下の説明「一部のページだけ書き出すときは「ページを指定」で範囲（例: 1-5, 8）を入れます。」
- ファイル名の行に zip 名（`svg_export.zip`）も併記する。
- 緑カードを 1 行の注記「文字は文字のまま書き出します（後から検索・再編集できます）。使ったフォントだけを埋め込みます。」に置き換える。
- フッターの案内: 複数なら「N 個の SVG を zip にまとめて保存します」、1 個なら「1 個の SVG を保存します」。
- グレーモードのまとめ・範囲（`#exp-modes-gray`）は現行のまま。

## 4. 状態とデータ

### 4.1 クライアントの状態（`state.js`）

- 撤去するフィールド: `status2` / `status3` / `changed2` / `changed3` / `selFor` / `guarding`。
- 追加するフィールド:
  - `scanned: boolean[]`（通しページ。`state` の `scanned[]` をそのまま持つ。旧形式で無ければ全 false）。
  - `matches2: {applied: number, pending: number}[]`（通しページ。`state` の `matches2` から）。
  - `edits3: {removed: number, borders: number, covers: number}[]`（通しページ。`state` の `edits3` から）。
- `filterFor` の既定は `{2: "matched", 3: "all"}`。値は手順 2 が `"matched" | "all"`、手順 3 が `"all" | "edited"`。
- 撤去する関数: `counts` / `pass` / `initStatus` / `mergeStatus` / `statusArr` / `statusOfCur` / `nextPending` / `firstPending` / `selSet` / `selKeys` / `selCount` / `clearSel`（レールの選択集合そのものが無くなる。手順 3 の要素・矩形の選択は現行どおり `resetPhaseUi` と `rect-overlay.js` の `clearSel` が担い、`state.js` 側の同名関数が消えることで `rect-overlay.js` のコメントにある名前衝突の注意も不要になる）。
- 判定関数の置き換え:
  - `skipsPhase2()` = `TOTAL > 0 && scanned.every(Boolean)`。
  - `firstEditablePage2()` = 一致のあるページの最初、無ければ `scanned` でない最初のページ、無ければ 0。
  - `scannedFiles()` は撤去し、ファイル別のスキャンページ数 `scannedCountOf(fileIndex)` を置く（`FILE_START` と `scanned` から数える。バナーとバッジが使う）。
  - `railPages(phase)`: 絞り込みを通したページ index の配列（レールとファイル行の件数はこれを通す。手順 2 は `scanned` を常に除く）。
  - `nextMatched(from)`: 手順 2 の「次の一致ページ」。
  - `exportPageList` から `noskip` 分岐を消す。
- `applyState` はページ列が同じでも違っても `scanned` / `matches2` / `edits3` を毎回そのまま取り込む（引き継ぐ状態が無くなるため `mergeStatus` は不要）。`collapsed` はページ列が変わったときだけ捨てる（現行どおり）。
- `advancePhase` は `guarding` を触らない。それ以外は現行どおり。

### 4.2 `state` RPC（`rpc_methods.py`）

- `changed2` / `changed3` を廃止し、代わりに次を返す:
  - `matches2: [[applied, pending], ...]`（通しページ順。`applied` は置換済み `dict_match` の数、`pending` は未適用候補の数。`planPage` と同じ数え方で、`_page_has_replacements` はこの数から導く）。
  - `edits3: [[removed, borders, covers], ...]`（`removed` は `removedList` が返す件数、`borders` は `borderList`、`covers` は `coverList` の件数。数え方は各 RPC と同じ述語を関数に切り出して共有する）。
- `scanned[]` / `scannedPages` / `ocrPages` / `truncated` / `noBackground` は現行どおり。
- 全ページ分を毎回数えるため、`reloadState` の呼び出し頻度は変えない（編集のたびに 1 回）。要素数の上限（`MAX_PAGE_ELEMENTS` / `MAX_DOC_ELEMENTS`）の範囲で線形に収まる。

### 4.3 手順 3 の右パネルのデータ

- 表示中ページの `removedList` / `borderList` / `coverList` の 3 本を引いて描く。枠線と上書きの「削除」は現行の `applyDelete` を使う。編集後は現行どおり `afterEdit`（`invalidate` → `reloadState` → `render`）。

## 6. テスト方針

- 単体（実ブラウザの `state.js` / 新 `page-jump.js` / `rail.js`）:
  - `applyState` が `scanned` / `matches2` / `edits3` を取り込むこと、`skipsPhase2` / `firstEditablePage2` / `railPages` / `nextMatched` / `scannedCountOf` の境界（0 件・全スキャン・混在・ファイルまたぎ）。
  - `exportPageList` に `noskip` が無いこと（3 モードの動作は現行のまま）。
  - ページ移動部品: 番号入力の範囲外・Enter・前後の端・ファイル切り替えで `S.page` が正しく変わること。
- サーバ（`test_web_rpc.py`）: `state` が `matches2` / `edits3` を返し、置換・戻す・削除・枠線・上書きの後に件数が変わること。`changed2` / `changed3` が無いこと。
- E2E（`test_pdftosvg_app_flow_e2e.py`）:
  - 4 手順の通し（`test_four_step_flow`）を、ガード無し・「次へ」だけで進む形に書き換え。レールのタグ（置換 / 未置換、削除 / 枠線 / 上書き）と件数カード、手順 4 の表を確認。
  - 手順 1: 全スキャン・混在それぞれでバナーの文言とカードのバッジ、モーダルが無いこと、「次へ」で止まらないこと。2 択カードでグレーモードに入れること。
  - ページ移動: 番号入力と前後ボタンで表示ページが変わり、レールに出ていないページへも行けること。
  - 既存の「案内モーダル」3 本は撤去し、上記に置き換える。
- 既存テストのうち `status2` / `status3` / `pending` / `skipped` / `noskip` / `guard` / `pageact` / `skip2` / `chk-gray` / `#sum-2` に依存するものは、この仕様に合わせて書き換えるか撤去する（調査で列挙済み: `test_pdftosvg_state_js.py` の状態・遷移・`na` 系、E2E の `_advance_step3_to_step4` / `_open_second_page_in_step3` ほか）。

依存の少ない順に 4 段階に分け、各段階でテストを緑にしてからコミットする。
