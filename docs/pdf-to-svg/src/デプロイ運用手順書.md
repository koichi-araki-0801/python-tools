本書は PdfToSvg を社内端末へ配布・運用するための手順を、情報システム担当向けにまとめたものである。ツールの内部構造は別冊「PdfToSvg 詳細設計書」を参照。

# 1. 配布方針

PdfToSvg は**インストーラを持たない**。PyInstaller の onedir 形式でビルドした `dist/PdfToSvg/` フォルダを**そのままコピー**して配る、ポータブル配布方式を取る。

- レジストリを使わない／管理者権限不要。ユーザー権限のまま動く。
- 辞書・設定・ログは**利用者ごとの `%LOCALAPPDATA%\PdfToSvg\data\`** に置く。プログラムフォルダ（exe と DLL のある場所）へは書き込まない。
- UI は OS 標準の Microsoft Edge をアプリモードで開くため、Chromium ランタイムは同梱しない（配布物 ~50MB）。

## 1.1 データ置き場と配布フォルダの権限（必読）

可変データ（辞書・設定・ログ・一時ファイル）の置き場は次の順で決まる。

| 優先 | 置き場 | 使われる条件 |
|---|---|---|
| 1 | 環境変数 `PDFTOSVG_DATA_DIR` が指すフォルダ | 明示指定したとき（USB などでの可搬運用・検証用） |
| 2 | exe と同じ場所の `data\` | 旧版からの引き継ぎ。既に `data\dictionary.json` がある配布フォルダのみ |
| 3 | `%LOCALAPPDATA%\PdfToSvg\data\` | 既定（新規展開時） |
| 4 | exe と同じ場所の `data\` | `%LOCALAPPDATA%` が使えない／書き込めない端末のフォールバック |

> [!WARN] **配布フォルダ（`PdfToSvg\`）は、それを使う利用者以外が書き込めない場所へ置くこと。**
> 同フォルダの `_internal\` には CPython ランタイム DLL と PyMuPDF のネイティブモジュールが入っており、Windows は exe と同じ場所から DLL を解決する。複数人が書き込める共有ツールフォルダや共有ドライブへ置くと、他の利用者が DLL を差し替えるだけで**次に起動した人の権限で任意のコードが動く**。
>
> - 推奨: 利用者ごとに自分のプロファイル配下へ展開する（この場合、権限の境界がそもそも無い）。
> - 共有配置がどうしても必要なら、配布フォルダの ACL を**利用者へは読み取り＋実行のみ**（書き込みは情報システム担当のみ）に設定する。既定のデータ置き場はプログラムフォルダの外なので、読み取り専用でも動作する。
> - 上表の 4（フォールバック）に落ちた端末では、プログラムフォルダ内の `data\` に書き込みが必要になる。その端末では ACL を分けて `data\` にだけ書き込みを許可すること。

## 1.2 ネットワークドライブ（マップドライブ / 共有フォルダ）での運用

- **exe はネットワークドライブから直接実行せず、ローカルへコピーして使うのを推奨する。**
  onedir 配布は CPython ランタイム DLL と PyMuPDF のネイティブモジュールを起動時〜実行中に
  随時読み込むため、共有から直接実行すると起動が遅くなるうえ、**実行中に共有への接続が
  切れると即クラッシュする**（遅延ロード中の DLL ページインが解決できない）。配布置き場と
  して共有に置くこと自体は問題ない（その場合は 1.1 の ACL 要件＝読み取り＋実行のみを守る）。
- **辞書を複数人で共有したい場合**は、各利用者の端末で `PDFTOSVG_DATA_DIR` を共有フォルダ内の
  同じフォルダへ向ける。同時更新は「先に保存した人が勝ち、後の保存は『他の利用者によって
  更新されています』のエラーで止まる」動きになる（相手の追加を黙って消さないための仕様。
  エラーが出たらアプリを再起動して最新の辞書を読み直す）。一時ファイル・ログは共有へは
  置かれない（利用者ごとのローカル領域に出る）。

# 2. ビルド手順

ビルドはネットワークのある開発端末で行う。`pdf-to-svg\scripts\build.bat` をダブルクリックするだけでよい。

1. `scripts\build.bat` が隔離 venv（`.venv-build`）を作成し、ビルドに必要な依存のみインストールする。
2. `pyinstaller packaging/pdftosvg.spec --clean --noconfirm --distpath dist --workpath build` で onedir exe を生成する。
3. 成果物 `dist/PdfToSvg/`（`PdfToSvg.exe` + `_internal` + `resources` + `fonts`）が出力される。

コマンドで実行する場合:

```
python -m pip install pyinstaller
pyinstaller packaging/pdftosvg.spec --clean --noconfirm --distpath dist --workpath build
```

`packaging/pdftosvg.spec` は `PySide6` / `shiboken6` を除外し、`fonts/` と `resources/` を datas として同梱する。データ置き場（既定 `%LOCALAPPDATA%\PdfToSvg\data\`）は初回起動時に自動生成される。

# 3. ビルド後の確認（チェックリスト）

配布前に、ビルド端末で次を確認する。

- `dist/PdfToSvg/` に `QtWebEngineProcess.exe` / `*.pak` / `locales/` / ICU / Qt DLL が**無い**こと。
- `fitz`（PyMuPDF）のネイティブ DLL が `_internal` に揃っていること。
- **ネットワーク遮断下でも起動・書き出しができる**こと（外部通信に依存しないことの確認）。
- `PdfToSvg.exe` をダブルクリックして Edge のアプリ窓が開き、4 ステップを一巡して SVG を書き出せること。

> [!INFO] Edge は Windows 10 / 11 に標準搭載のため別途配布は不要。万一 Edge が無い端末では起動できないので、対象端末に Edge があることを事前に確認する。

# 4. 配布・展開

1. `dist/PdfToSvg/` フォルダを ZIP などにまとめ、共有フォルダや配布メディアで対象端末へ渡す。
2. 受け取った端末では任意の場所（デスクトップ・業務フォルダ等）へ展開する。インストール操作は不要。
3. `PdfToSvg.exe`（または開発用に `run.bat`）をダブルクリックして起動する。

# 5. 辞書の配布・共有

用語辞書は端末ごとに `dictionary.json`（既定は `%LOCALAPPDATA%\PdfToSvg\data\`。1.1 節の表を参照）として持つ。共通の辞書を配るには次のいずれか。

- **ファイル配布**: マスタ辞書 `dictionary.json` を各端末のデータ置き場へ上書きコピーする。
- **UI 経由**: 配布元で「辞書」タブの **「JSON書き出し」**、受け取り側で **「JSON読み込み」** を使う（操作手順書 8 章参照）。

辞書は NFKC 正規化で全角/半角差を吸収する。登録件数は **20,000 件が上限**で、超える取り込みは理由付きで拒否される。フォーマットが壊れた要素（配列の中に文字列や数値が混ざっている等）は読み飛ばし、件数を画面に通知する（黙って消さない）。フォーマットは次の通り（人手編集可）。

```
[
  {"source": "元の語", "target": "置換後の語", "enabled": true},
  {"source": "Old Header", "target": "New Header", "enabled": false}
]
```

# 6. 運用・トラブル対応

| 事象 | 対処 |
|---|---|
| アプリ窓が開かない | 数十秒待って再度起動。データ置き場の `logs\startup.log`（既定は `%LOCALAPPDATA%\PdfToSvg\data\logs\startup.log`。1.1 節の表の順で決まる）に起動診断が出るので確認（exe は console 非表示のため stderr の代替）。 |
| VDI/リモートデスクトップでアプリ窓がクラッシュする | 本ビルドは端末標準の「管理された」既定 Edge と同じ構成で開き（特殊フラグ無し）、ファイルの開く/保存もネイティブダイアログを使わない（従来型ダイアログ + ダウンロード）ため VDI でも安定するよう対策済み。なお落ちる場合は上記の `startup.log` を情報システム担当へ。Edge 側の詳細が要るときは、環境変数 `PDFTOSVG_EDGE_LOG=1` を設定してから再現させ、`%LOCALAPPDATA%\PdfToSvg\logs\edge.log` を渡す（既定では出力されない。既定プロファイルで開くため、常時出力すると Edge セッション全体の記録が利用者の端末に溜まり続けてしまう）。 |
| PDF が選べない / ダイアログで固まる | エクスプローラーからウィンドウへ PDF を**ドラッグ＆ドロップ**でも読み込める。 |
| 保存先が選べない | 仕様（VDI 安定化のため）。保存はブラウザのダウンロードフォルダへ出力される。 |
| 端末に Edge が無い | Edge を導入（Win10/11 は標準搭載）。アプリモード表示に Edge が必須。 |
| 辞書が反映されない | 「全ファイルに再適用」を実行（ヘッダ・本文を問わず全文が対象）。 |
| 別端末へ丸ごと移したい | 配布フォルダをコピーしたうえで、辞書は「JSON書き出し」→ 移行先で「JSON読み込み」で移す（データ置き場は既定で利用者プロファイル配下のため、フォルダコピーでは移らない）。持ち歩き運用にするなら `PDFTOSVG_DATA_DIR` を配布フォルダ内の `data` に向ける。 |
| 辞書が空で始まった／件数が減った | 起動時に「辞書ファイルを読み込めませんでした」「N 件を読み飛ばしました」の通知が出ていないか確認する。壊れた要素は読み飛ばして起動する仕様で、元ファイルは `data\dictionary.json` に残っている。 |

終了は窓を閉じた時の `/quit` ビーコン、または `/ping` 途絶を見張る idle watchdog（60 秒）で行われる。黒いコンソール窓（ソース起動時）は閉じないこと。

# 7. ライセンス運用上の注意

> [!WARN] 本ツールは **PyMuPDF (AGPL)** に依存するため、**社内 / 身内限定の配布**を前提とする。外部・商用配布が必要になった場合は、抽出部 `engine/pdf_engine.py` を BSD ライセンスの **pypdfium2** 等へ差し替えるか、Artifex の商用ライセンスを取得すること。

同梱フォント（BIZ UDPゴシック / Noto Serif JP）はいずれも **SIL OFL 1.1**（`fonts/OFL-*.txt`）で再配布可。SVG 出力時は使用グリフのみを WOFF2 サブセットで埋め込むため、ライセンス表記を保ったまま軽量に配布できる。
