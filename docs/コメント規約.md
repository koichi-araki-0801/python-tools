本書は本リポジトリの**全コードのコメントに関する唯一の正典**である。コード修正時は
**既存・新規いずれのコードも必ず本規約に従う**こと。各 `README` や設計書からは
本書を参照するに留め、規約の実体は本書に一元化する（重複を作らない）。

> 由来: 本規約は pie-chart で確立した運用を全言語へ昇格させたもの。pie-chart 固有の
> 「出力不変の検証（`out/_baseline` との byte-diff）」だけは pie-chart に密なため
> `pie-chart/README.md` 側へ残す（本書の「3. 検証」からも参照する）。

## 0. 位置づけ / 適用範囲

- 対象: `editor` / `pdf-to-svg` / `pie-chart` / `graph-editor` / `offline` / `docs` ほか
  リポジトリ内の全ソース。
- 対象拡張子: `.ts` `.tsx` `.js` `.cjs` `.mjs` `.vue` `.py` `.ps1` `.bat` `.md`。
- 強制の仕組み: 機械判定可能な項目を検査する CI チェック
  (`scripts/check-comments.mjs` / `pnpm run check:comments`) を備える (詳細は「3. 検証」)。

## 1. 共通原則（言語非依存）

すべての言語のコメントは次の 6 原則に従う。体裁の差異は「2. 言語別付録」で吸収する。

1. **何を書くか**: 「なぜ」「非自明なロジック」を説明する。自明な what は書かない
   （コードを読めば分かることを繰り返さない）。**過去の経緯も書かない** — 移植元・分離元、
   変更日、レビュー所見番号、工程名（フェーズ等）といった「どこから来たか・いつ変えたか」の
   記録は git 履歴と docs 側の設計書が持つ。現在も効いている制約は、経緯の語りでなく
   **現在形の理由**として書く（例: 「以前は X だったが壊れた」→「X にすると〜が壊れる」）。
   過去の事実だけを根拠にする禁止事項（「〜へ戻さない（過去に壊れた実測）」）は、コメントには
   禁止事項だけを書き、根拠は設計正典の「却下済み設計」節へ委ねる。レビュー所見番号
   （「所見」+ 番号、英字 F/P/R + 番号、root + 英字番号、run + 番号）はコメント行・テスト名・
   docs 原稿から機械検査で締め出す（`check:comments` のハード失敗）。誤検知が出たら
   除外表を足すのではなく文面を直す。
2. **言語**: 日本語の散文 + 英語ドメイン用語を併用する。ドメイン用語
   (`pieRadius` / `anchor` / `leader` / `cascade` / `viewBox` 等) は無理に和訳しない。
3. **識別子はバッククォート**: 関数名・型名・定数・フィールド/変数名・ファイル名を指す時は
   `` `runCascadeOnce` `` のようにバッククォートで囲む（JSDoc / docstring / クロスファイル
   参照では必須）。散文中の概念語 (leader, rim, cascade 等)、`「その他」` のような `「」` 内
   デバイス名、ランク記号 ①〜⑨ は囲まない。
4. **クロスファイル参照**: 「他ファイルの定義を見よ」は `` `<basename>.<ext>` の `<symbol>` ``
   形に統一する（例 `` `layout.ts` の `markTopBandSmallRight` ``）。兄弟ファイルは basename で
   一意なのでディレクトリ接頭辞は付けない。
5. **重複は集約**: 同じ仕組みの説明を複数箇所に散らさない。正典（実装/発火点）を 1 つ決め、
   他所はそこへの相互参照に短縮する。
6. **体裁の共通則**: 1 行はおおむね 100 桁以内。コメント本文の括弧は ASCII `()` を使う
   （`「」` 内を除く）。

## 2. 言語別付録

### A. TypeScript / JavaScript（`.ts` `.tsx` `.js` `.cjs` `.mjs` `.vue`）

- **ファイル先頭**: `=` 罫線の装飾ボックスヘッダ。1 行目と 3 行目が `=` 罫線、2 行目が
  `<ファイル名> — <簡潔な説明>`（ハイフンは ` — ` 全角ダッシュ）。必要なら直後に
  `役割:` / `ファイル内構成:` 等の散文を続ける。

  ```ts
  // =============================================================================
  // layout.ts — 円グラフのラベル配置(論理座標上での配置決定)
  // =============================================================================
  ```

- **節区切り**: 関数内/ファイル内の区切りは `// ── N. ラベル ──` を使う
  （第 3 の区切りスタイルを増やさない）。

  ```ts
  // ── 1. profiles — slice 分類とプロファイル構築 ──
  ```

- **シンボル説明**: 関数・型・公開定数の説明は JSDoc `/** ... */`。JSDoc 内とクロスファイル
  参照では識別子バッククォートを必須とする。
- biome 対象（`editor/**` / `pie-chart/**`）は `lineWidth=100` が format で担保される。

### B. Python（`.py`）

- **モジュール先頭 docstring**: ファイル冒頭に `"""..."""` で役割サマリを置く。
  日本語散文 + 英語ドメイン用語、識別子はバッククォート。

  ```python
  """Markdown / xlsx.yaml 原稿 → 閲覧用 HTML 集約レンダラ。

  `docs/<project>/src/` を正典とし、読者別（guide/spec）の 2 冊へ集約する。
  """
  ```

- **クラス/関数 docstring**: 公開クラス・関数には docstring を付ける。Google / NumPy 形式は
  採らず、散文を基本とし、必要に応じて `Args:` / `Returns:` を簡潔に添える。
- **節区切り**: モジュール内の区切りは `# ── ラベル ──` を使う（TS の `// ── N. ──` に対応）。
- エンコーディング: ソースは UTF-8。BOM は不要（BOM 必須は `.ps1` のみ）。

### C. PowerShell（`.ps1`）

- **先頭 comment-based help**: ファイル冒頭に `<# ... #>` の help ブロックを置き、
  `.SYNOPSIS` / `.DESCRIPTION` / `.PARAMETER` / `.EXAMPLE` を日本語で記述する。

  ```powershell
  #requires -Version 5.1
  <#
  .SYNOPSIS
    オフライン重量物とソースコードを GitHub Releases へ公開する。
  .DESCRIPTION
    コードは git 履歴で管理し、重量物は Releases に置く（理由を散文で）。
  .PARAMETER Tag
    公開先のローリングタグ。既定 offline-bundle-v1。
  #>
  ```

- **エンコーディング**: 日本語（非 ASCII）を含む `.ps1` は **UTF-8 BOM 必須**
  （cp932 環境での文字化け回避）。先頭 3 バイトが `EF BB BF` であること。
- 行内コメントの節区切りは `# ── ラベル ──`。

### D. `.bat` ランチャ

- 本文は **ASCII 主体**。非 ASCII を使う場合は冒頭で `chcp 65001 >nul` を入れる。
- `.ps1` を新規追加する時は **同名 `.bat` ランチャを必ず併設**する
  （置き場ルールと入口一覧はルート `README.md`「スクリプトの置き場ルール」節を正典とする）。

### E. Markdown（`.md`）

- 正典集約の原則（共通原則 5）に従う。規約・仕様の実体は正典 1 箇所に置き、他所は参照に
  短縮する。本書はコメント規約の正典であり、他所からは本書を参照する。

## 3. 検証

コメントのみの変更は**挙動・出力を変えない**こと。領域別の確認:

- **editor**: `pnpm run check:ci`（biome）+ `pnpm run typecheck`（`@editor/shared` 先行
  ビルド込み）。コミット前に `pnpm exec biome check --write editor/<対象>` を先行実行して
  lint-staged のステージ取り違えを防ぐ。
- **pie-chart**: `npm run batch` 後、`out/svg_js` と `out/_baseline` を SHA256 で byte-diff し
  **完全一致**を確認する（pie-chart 固有・鉄則。`pie-chart/README.md` が正典）。
- **pdf-to-svg / docs / graph-editor**: 各 smoke / テスト（`build_all.py` 実行で HTML 生成が
  green・pytest・`pnpm --filter graph-editor run test` 等）が通ること。
- **.ps1**: 先頭 3 バイトが `EF BB BF`（BOM 維持）であること。
- **横断チェック**: `pnpm run check:comments`（機械判定可能な項目: `.ps1` の BOM、`.ps1`↔`.bat`
  併設、コメント行・テスト名・docs 原稿のレビュー所見番号、装飾ボックスヘッダ有無等）が
  通ること。CI 集約 `pnpm run ci` にも組み込む。

## 4. 改訂手順

- 本書 (`docs/コメント規約.md`) がコメント規約の**唯一の正典**である。
- 規約を変更する時は本書を更新する。`README` / 設計書は本書への参照に留め、
  要点をコピーして二重管理しない（重複は集約の原則）。
